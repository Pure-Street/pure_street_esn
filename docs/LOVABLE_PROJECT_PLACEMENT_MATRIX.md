# Lovable Project Placement Matrix

## Purpose

This document preserves the major Lovable/STREETS project lines and defines where they should live in the public ecosystem so `oaklandstreets.live` remains polished, strategic, and funder-ready rather than becoming an online notebook.

Nothing in this matrix should be merged into public navigation until the production source of truth is confirmed.

---

## Global rule

The public STREETS site must remain beautiful, animated, high-definition, and enticing.

The homepage should function as the flagship civic-tech experience:

- cinematic but fast
- animated but not gimmicky
- high-contrast and high-definition
- map/data-forward
- emotionally compelling without overclaiming
- visually credible to funders, cities, corridor partners, and residents
- immediately clear about the Oakland pilot and Pure Street action layer

The homepage should not become a repository of every proposal, subsite, legal note, city plan, architecture memo, or future feature.

---

## Public homepage design standard

The opening page should retain or improve:

- animated hero sequence
- civic-tech command-center feel
- Oakland corridor visual language
- motion-based report-to-action workflow
- dashboard preview cards
- report category animation
- pilot metrics blocks
- Pure Street service/action layer
- partner/funder CTA
- STREETS Dispatch preview
- polished mobile responsiveness

Primary homepage message:

> STREETS helps Oakland see recurring street conditions clearly enough to act on them.

Homepage proof modules:

- Dashboard preview
- Report categories
- Sample condition report
- Oakland pilot card
- Pure Street action layer
- Partner CTA
- Metrics cards
- Before/after documentation placeholder
- STREETS Dispatch articles

## Lovable integration rule

When reconnecting or embedding Lovable-generated projects:

- Confirm the correct production source before copying code.
- Preserve existing Lovable project URLs and screenshots in documentation.
- Do not overwrite production with a visually weaker version.
- Promote the most polished version of each city/project.
- Link dedicated projects from the main STREETS ecosystem only when their copy, disclaimers, and visual quality are public-ready.
- Keep speculative technical architecture as roadmap/internal documentation unless currently implemented.

---

## Quality bar before public launch

Every public page or dedicated city site must pass this standard:

- It looks intentionally designed, not auto-generated.
- It has a clear audience and action.
- It does not overclaim partnerships, authority, technology, or services.
- It includes city-specific relevance.
- It links back to STREETS / Pure Street coherently.
- It has a polished mobile view.
- It supports funder confidence within 90 seconds.

---

## Final directive

Preserve all projects. Publish only the strongest public face.

`oaklandstreets.live` should remain the flagship product experience. Lovable-generated city sites, proposal pages, and company-profile pages should plug into the ecosystem as dedicated, polished modules — not as raw notes pasted into the homepage.
